# План MVP

## Цель

Получить воспроизводимую локальную демонстрацию замкнутого цикла:

```text
мухобойка → визуальный вход → MaleCNS → команда → движение мухи
```

Первый MVP доказывает работу контура управления. Пластичность и утверждения об обучении добавляются только после проверки сенсорного входа и причинного влияния readout-нейронов.

## Этап 1. Игровой прототип

- Создать Go-сервер с WebSocket endpoint.
- Создать React/TypeScript frontend с Canvas.
- Реализовать авторитетное состояние игры на backend:
  - положение, скорость и направление мухи;
  - положение и фаза удара мухобойки;
  - номер тика и состояние эпизода.
- Реализовать команды `turn_left`, `turn_right`, `straight`, `escape`.
- Добавить временный случайный контроллер.
- Добавить столкновение, перезапуск эпизода и счётчик времени выживания.

Критерий готовности: игра стабильно работает в браузере, а backend полностью воспроизводит эпизод по seed и журналу пользовательского ввода.

## Этап 2. Интерфейс neural worker

- Зафиксировать версию и лицензию MaleCNS-реализации.
- Не переносить весь симулятор в Go: запускать проверенное native/Python-ядро отдельным долгоживущим процессом.
- Определить IPC-протокол:
  - `reset(seed)`;
  - `step(frame, neural_duration_ms)`;
  - `feedback(kind)`;
  - `checkpoint(path)`;
  - `restore(path)`.
- Добавить таймаут, health check и безопасный fallback на `straight`.
- Записывать версию модели, checksum данных и параметры каждого запуска.

Критерий готовности: backend получает детерминированный neural response на фиксированную последовательность входов без перезапуска мозга между тиками.

## Этап 3. Зрительный вход

- Рендерить чистый сенсорный кадр без HUD и скрытых координат.
- Проецировать изображение на R1–R6 и R8 по адаптеру MaleCNS.
- Начать с контрастного объекта на однородном фоне.
- Проверить реакции на:
  - пустой кадр;
  - объект слева и справа;
  - приближающийся объект;
  - статичный объект;
  - инвертированные цвета.
- Публиковать сенсорный кадр рядом с основной анимацией.

Критерий готовности: изменения входа воспроизводимо меняют активность визуального тракта и выбранных readout-нейронов.

## Этап 4. Neural decoder

- Выбрать биологически мотивированные descending/escape neurons.
- Зафиксировать механический decoder до оценки игровых результатов.
- Использовать разность левой и правой активности для поворота.
- Использовать отдельный escape-readout для краткого ускорения.
- Не передавать декодеру координаты мухобойки, столкновения или будущие состояния.
- Добавить визуализацию spike counts и фактического решения.

Критерий готовности: положение или приближение объекта причинно влияет на игровые команды, а black-frame и shuffled-input контроли разрушают этот эффект.

## Этап 5. Базовый эксперимент без обучения

- Запустить одинаковые наборы эпизодов для:
  - neural controller;
  - random controller;
  - constant-straight controller;
  - decoder с перемешанными readout-сигналами.
- Измерять:
  - медианное время выживания;
  - долю успешных уклонений;
  - задержку реакции;
  - распределение команд;
  - частоту спайков readout-нейронов.
- Использовать фиксированные train/test seeds сценариев мухобойки.

Критерий готовности: сохранён воспроизводимый отчёт, даже если neural controller не превосходит baselines.

## Этап 6. Экспериментальная пластичность

- Добавить aversive pulse после попадания.
- Добавить reward только после завершённого успешного замаха, не за каждый тик выживания.
- Сохранять изменяемые веса и eligibility traces.
- Сравнить:
  - plasticity on;
  - frozen weights;
  - shuffled feedback;
  - reset learned weights;
  - несколько независимых seed.
- Оценивать результат только на отложенных траекториях мухобойки.

Критерий готовности: улучшение повторяется на независимых запусках, исчезает при сбросе памяти и отсутствует в контрольных условиях.

## Этап 7. Публичное демо

- Добавить режим наблюдения без возможности влиять на серверный эксперимент.
- Показывать:
  - фактический сенсорный кадр;
  - neural time и wall time;
  - readout и выбранную команду;
  - controller/model/checkpoint;
  - результаты baselines;
  - явный статус `learning unproven` или подтверждённый результат.
- Записать короткое видео и опубликовать воспроизводимую конфигурацию.

## Порядок ближайшей реализации

1. Инициализировать Go-модуль и Vite frontend.
2. Поднять WebSocket-контур со случайным контроллером.
3. Реализовать механику мухи и мухобойки.
4. Добавить журналирование и deterministic replay.
5. Подключить neural worker без пластичности.
6. Провести сенсорную калибровку.
7. Зафиксировать decoder и baselines.
8. Только затем экспериментировать с reward и памятью.
